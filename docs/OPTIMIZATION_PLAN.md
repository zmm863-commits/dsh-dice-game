## 〇、现状体检

| 玩法 | 深度 | 平衡 | 反馈 | 一句话诊断 |
|---|---|---|---|---|
| 吹牛 | ★★★ | ★★ | ★★ | 规则骨架最佳，但 AI 是裸随机阈值，玩两局即被看穿 |
| 猜红点 | ★★ | ★★ | ★★ | ①④红点天然二项分布(p=1/3)的概率结构完全没进玩法 |
| 猜红蓝 | ★★★ | ★★ | ★★ | 双维叫点是六玩法中最有差异化的，惜被 AI 乱叫拖累 |
| 猜大小 | ★ | ★★★ | ★ | 50/50 抛硬币，无赔付差异＝零期望且低方差，无聊 |
| 猜单双 | ★ | ★★★ | ★ | 数学上绝对公平，也因此绝对平淡 |
| 猜顺子 | ★ | ★ | ★ | 命中率约 11% 却无赔付补偿，纯挫败收集器 |

**三大结构性病灶**
1. **无持久化**：opaque iframe 使 localStorage 静默失败，语言/战绩刷新全丢；
2. **无经济**：只有「你 X 胜 / 电脑 Y 胜」两个会话计数器，无筹码/赔率/方差体验；
3. **无模型 AI**：六个 computer*Turn() 全是硬编码阈值＋随机噪声，难度不可调、行为可预测。

## 一、数值与赔率设计（先算清楚，再谈手感）

### 1.1 直接押注类概率基线（3骰，样本空间 216）
- **猜大小**：P(小)=108/216=50.0%（含 111/222/333），P(大)=50.0%（含 444/555/666），P(围骰)=6/216≈2.78%。
- **猜单双**：3骰之和奇偶各恰 108/216=50%（1 或 3 个奇骰=81+27=108），天然零边。
- **猜顺子**：{123,234,345,456}×6排列=24/216≈11.1%，公平赔付=216/24=**9×**。

### 1.2 建议赔付表（所有倍数均为 [PLACEHOLDER]，上线前蒙特卡洛 10 万次验证 RTP±3%）

| 玩法 | 押项 | 命中率 | 公平倍数 | 建议实付 | 设计意图 |
|---|---|---|---|---|---|
| 大小 | 大/小 | 50% | 2.00× | 1×＋围骰彩金2× | 彩金使 EV 由 0→+5.6%，娱乐向正期望（故意为之，见原则框） |
| 大小 | 围骰(新增押项) | 2.78% | 36× | 35× | 彩票型长尾钩子 |
| 单双 | 单/双 | 50% | 2.00× | 连中递增 1×→1.5×→2×封顶 | 用赔付曲线造方差，弥补概率对称的无聊 |
| 顺子 | 任一顺子 | 11.1% | 9× | 10× | 微正期望补偿挫败感 |
| 红点 | ≥2红(5骰,p=1/3) | 53.9% | 1.86× | 1.8× | 二项分布 P(0..5)=13/33/33/16/4/0.4% |
| 红点 | ≥3红 | 20.6% | 4.86× | 4.5× | 中风险档 |
| 红点 | 5红全红 | 0.41% | 243× | 200× | 全红头奖，社交截图点 |
| 红蓝 | 精确X红Y蓝(5骰) | 最高单项(2,2,1)仅12.3% | ~8× | 分层：精确20×/差一3×/差二回本 | 多项分布太苛刻，必须分层否则劝退 |

> **设计原则**：本作是 PvE 娱乐品不是赌场，允许整体 +5%~+10% 正 EV 换留存；但严禁任何「无限刷分回路」（筹码化时需对每小时收益上限建模封顶）。

## 二、吹牛 AI 升级（二项分布胜率模型）

### 2.1 模型
已知自己 a 个某面、场上未开盅 m=10 骰，单骰命中 q=1/6（若保留 1 为百搭则 q=1/3，需核实规则）：

```
pTrue(call) = P( Binomial(m, q) ≥ call.count − a )   # 对手叫点为真的概率
```

### 2.2 决策伪代码
```
function aiDecide(myDice, currentCall):
    a = count(myDice, currentCall.face);  m = 15 − 5(自己)
    pTrue = binomTail(m, q, currentCall.count − a)
    if pTrue < θ:                          # 低于阈值 → 判吹牛，开盅
        return CHALLENGE
    best = argmax_f( count(myDice,f) + m*q )           # 期望可辩护的面
    n    = ceil(count(myDice,best) + m*q) + noise()     # 加噪声保人味
    if rand() < β and n > currentCall.count:            # 偶发诈唬，保留人味
        return CALL(secondBestFace, currentCall.count + 1)
    return CALL(best, max(currentCall.count + 1, n))
```

### 2.3 难度分档（阈值/噪声/延迟三轴联动，替代固定 1200ms）

| 档位 | 挑战阈值θ | 诈唬率β | 叫点噪声 | 思考延迟 | 附加能力 |
|---|---|---|---|---|---|
| 新手 | 0.28 | 5% | ±2 | 900–1600ms | 无 |
| 普通 | 0.42 | 12% | ±1 | 700–1500ms | 无 |
| 大师 | 0.55 | 8%(仅低成本时机) | 0~1 | 500–1200ms | 统计玩家历史叫点偏差做频率修正 |

验收锚点：普通档对中等玩家胜率≈50%；大师档自测胜率 <45% 才算达标 `[PLACEHOLDER]`。

## 三、单局节奏与重开动机
- **连胜挑战**：streak 计数＋🔥标识；每 3 连升称号（见习赌徒→桌面常客→老千→骰神），称号挂钩 AI 自动升降档，形成「越赢越难」的自适应曲线。
- **连败保护**：3 连败后下一局 AI 降半档＋首胜双倍计数，阻断 rage-quit；保护触发要有文案明示（诚实设计，避免作弊感）。
- **任务系统**：持久化就绪前做会话版（3 条随机小目标：赢 2 场大小／吹牛成功挑战 1 次／任意 3 连胜），完成给骰子皮肤碎片；存储桥落地后升级为每日刷新。
- **局内里程碑**：首胜、让二追三逆转、围骰彩金——toast 轻提示不打断流程。

## 四、反馈 Juice（全部纯前端，iframe 沙箱不影响 Audio API）
- **Web Audio 合成音效三件套**（零素材）：掷骰=带通滤波白噪 80ms；开盅=短促 click＋上扬双音；胜/负=大三和弦琶音／下行小三度。仅需首次用户手势 resume()；静音开关写入持久化键 `dice_muted`。
- **Confetti**：60 粒 CSS/rAF 粒子 800ms，仅 transform/opacity（GPU 合成）；连胜≥3 换金色粒子。
- **连胜火焰**：scoreboard 旁 🔥＋scale 脉冲动画。
- **震屏分级**：基于现有 shake-dice 改造三档 `.shake-s/m/l`（失败小、挑战失败中、围骰/头奖大）。
- **红线**：低端机 60fps；所有特效可在设置里一键关。

## 五、持久化破局【P0】——postMessage 存储桥

**问题**：sandbox 无 allow-same-origin → iframe 内 localStorage 抛 SecurityError 被 try/catch 吞掉（2034行附近），一切状态刷新归零。

**协议 DICE-SAVE v1**（收发两端都在本插件包内，完全可控）：

```
┌ iframe(index.html) ──────────┐    ┌ 宿主(client.js 新增 listener) ──┐
│ load 后发 hello{req}          │ →  │ 校验 event.source===iframe 引用 │
│                              │ ←  │ 回 ready{storage:'ls'|'mem'}   │
│ dice-get{key,req}            │ →  │ 读宿主 localStorage             │
│                              │ ←  │ dice-data{key,val|null,req}    │
│ dice-set{key,json,req}       │ →  │ 写入并回执                      │
│                              │ ←  │ dice-ok{req}                   │
│ hello 重试3次×250ms 无应答     │    │                                │
│ → 降级内存态＋UI提示「进度不保存」│   │                                │
└──────────────────────────────┘    └────────────────────────────────┘
```

**安全约束**：opaque origin 是字符串 "null"，不能按 origin 白名单——宿主只认 `event.source === iframe.contentWindow` 引用；key 强制 `dice_` 前缀白名单；value≤64KB JSON 并做截断防御。

**宿主侧存储面评估结论**

| 候选 | 判断 | 结论 |
|---|---|---|
| 宿主页面 localStorage | **已实证**：lib/client.js:218 现网代码即在宿主侧 `localStorage.getItem("dicePublicBase")`，宿主页面不受 sandbox 限制 | ✅ 主选（已验证） |
| 宿主 window 内存变量 | 刷新即失，仅作会话级兜底缓存 | ⚠️ 兜底 |
| 宿主 IndexedDB | 数据量 <10KB，异步复杂度不值得 | ❌ 不引入 |
| DSH 客户端 API 存储 | 抽查 lib/client.js 无公开通用存储接口，且无需——宿主 localStorage 已够用 | ❌ 不依赖 |

**降级链路**：iframe内 localStorage 直测 → 失败走 postMessage（宿主 localStorage）→ 再失败（单独打开/旧宿主）→ 内存态＋明确 UI 提示。
**写入策略**：关键事件即时写＋3s 防抖合并；存 `dice_lang / dice_stats / dice_muted / dice_streak / dice_tasks`。
**验收**：语言选择刷新保持；战绩跨刷新累计；隐私模式下不报错只降级。

## 七、新玩法候选（低成本复用现有骰子资产）
1. **极速骰**：3骰开出前 5 秒倒计时内连押大小/单双组合，连对翻倍——复用猜大小全部资产＋一个计时器，主打 30 秒一局的短平快多巴胺。
2. **骰王争霸**：双方各 3 骰比总和，差值=对方扣血，6 点=暴击双倍——复用骰子渲染与胜负结算，给数值党「有血条的成长感」，也是称号系统的最佳载体。
3. **一掷定音**：掷 3 骰享 2 次重掷，按牌型表（对子/顺子/围骰）计分——把顺子从一次性猜测扩成保留决策，教学成本极低，深度天花板最高。
